## 4. 결정이 필요한 것 (구현하지 않음)

1. **함수 리전.** 운영 함수는 `iad1`, DB는 `ap-northeast-2`. Vercel 프로젝트의 Function Region(또는 `vercel.json` `regions`)을 서울(`icn1`)로 옮기면 호출마다 여러 번인 순차 DB 왕복이 대륙 간이 아니게 된다. 효과는 **측정하지 않았다.** 배포 설정 변경이라 사용자 승인 사안이고, 요금제의 리전 선택 가능 여부는 확인하지 않았다. 측정안: 승인 시 프리뷰 배포 하나만 `icn1`로 두고 같은 읽기 전용 호출을 운영과 번갈아 n≥5회씩(단일 표본 비교 금지).
2. **예산 너머의 검색.** 지금 규칙은 "예산 안이면 `complete`, 넘으면 `partial`로 정직하게". 넘은 뒤에도 전체 검색을 보장하려면 (a) 검색이 읽는 표만 예산 상향(1,000행마다 순차 페이지 1회 추가 — 리전이 같으면 싸다), (b) DB 쪽 후보 필터 RPC(마이그레이션, 순위 동등성 설계 필요), (c) 저장소 범위 지정(입력 변경) 중 고른다. 권장: 1번 결정 뒤 파일럿에서 측정해 (a)부터.
3. **(선택) 느린·재시도 요청 로그.** 서버 Supabase 클라이언트의 fetch를 감싸 3 s 이상·`X-Retry-Count`·5xx 요청만 경로(쿼리 문자열 제외)·상태·시간 한 줄로 남기면, 다음 꼬리는 Vercel 로그만으로 갈린다. 약 40줄 + 테스트. 요청하면 구현한다.
