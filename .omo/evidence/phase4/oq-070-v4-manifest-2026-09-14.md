## What was wrong

graph-surface v1, v2 and v3 grade against the answer-manifest questions of
the frozen databrain manifest `tasks.v3.json` (loader digest
`7a317232…`). Between the databrain v3 release (2026-08-25) and
graph-surface v3 (2026-09-14) the product was renamed. Two facts stopped
existing in source:

| task | v3 fact (aliases) | the string in source today |
|---|---|---|
| `real-answer-receipt-statement` | `https://arr.dev/receipt/v1`, `arr.dev/receipt/v1` | `RECEIPT_PREDICATE_TYPE = "https://arr-app-web.vercel.app/receipt/v1"` (`packages/core/src/assurance/receipts.ts`; the old value is a rejected-predicate test case) |
| `real-answer-index-pr-limits` | `arr:begin`, `arr begin` | `ALRESCHA_INDEX_BEGIN = "<!-- ALRESCHA:BEGIN (managed — do not edit inside) -->"` (`packages/core/src/context/minimal-index.ts`) |

In graph-surface v3 every trial in both arms on those two questions scored
exactly 2/3 — PARTIAL by construction, not by behaviour.

## What changed

`tasks.v4.json` is the v3 file's text with **four aliases added** and
nothing else: the diff is six inserted lines. Every v3 alias survives in
place, so any answer that passed under v3 passes under v4; an answer that
quotes today's strings now passes too. A test grades one such answer under
both manifests and asserts 2/3 under v3, PASS under v4.

| manifest | loader digest (what a pre-registration pins) | file SHA-256 |
|---|---|---|
| `tasks.v3.json` — **frozen, untouched** | `7a317232cfb4f7c13db3e4c8c4f9bfd3f8eb26dd6f02dccc519b04ad77a9c2a7` | `9318cb67f723875221aef7db439f69e7ccf281de56af11dd364c7ad30ac32dd3` |

`scripts/graph-surface-benchmark/print-manifest-digest.ts` prints both.

## How the next run reaches it

A graph-surface pre-registration's `questionSource.manifest` was a
documentation field; the loader always read `tasks.v3.json`. It is parsed
now: a pre-registration names its manifest and pins that manifest's digest,
and the runner and the F5 audit resolve the name against the repository
root. The v1/v2/v3 files name `tasks.v3.json` and keep loading exactly as
before — their digests are unchanged, so their published reports still
audit clean. A pre-registration that names a manifest without a root to
resolve it **refuses** rather than falling back to v3; a v3 digest pinned
against the v4 file is a mismatch, not a run.

**No graph-surface v4 pre-registration is created here.** Which questions
the next run asks is settled (this file); what else it changes is OQ-071's
decision, and a pre-registration written before that decision would be a
lock on something nobody chose.

## What does not change

- The databrain v3 release (`results.v3.real.*`, 600 trials) ran on the
  pre-rename corpus and is unaffected; `verify-benchmark-report.ts` audits
  it against `tasks.v3.json` as before. `tasks.v4.json` is not a databrain
  release and is not added to that audit's release list — a v4 databrain
  run would be its own pre-registration.
- graph-surface v1/v2/v3 reports are frozen. Their PASS rates keep the 2/3
  cap on the two questions, and the v3 evidence says so.
