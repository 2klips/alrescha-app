> Plan text: "guardrail suites from Phase 1 (scope-fidelity, security,
> plan-compliance) still pass untouched."

**Verdict: PASS — and "untouched" is literal, not approximate.**

The claim has two halves and both are checked: the suites pass, **and** neither
they nor the fixtures and scripts they depend on were edited to make them pass.

### `plan-compliance` (4) — the meta-gate

Maps every shipped todo and mandatory boundary to executable proof
(`evidenceCount: 22`, `mustHaveCount: 22`, `mustNotCount: 10`,
`requiredBoundaryCount: 6`, `status: "pass"`, no failures), and independently
re-asserts that the repository's quality gates were not weakened: `pnpm lint`
still carries `eslint . --max-warnings=0`, `pnpm test` still `vitest run`,
`pnpm typecheck` still `tsc --noEmit`, and none of them contain
`passWithNoTests`, `noEmitOnError false` or `--force`.

That case matters here specifically: Wave 4 added devDependencies and new test
files, and this is the check that would have caught a gate loosened to
accommodate them. It passes.

Two mutation cases confirm the analyser still fails when it should — removing a
WORK_SPEC boundary, and mislabelling a proof kind.

### `security-audit` (7)

Unverified webhook payloads, plaintext token/provider-key logging, tenant tables
without RLS, persistence of raw repository source outside transient memory, and
HTML injection sinks in source-span rendering — all still rejected, with the two
legitimate exceptions (an explicitly publishable Supabase browser key, and RLS
enabled by a bounded migration loop) still accepted.

Relevant to this phase: the restyle rewrote every rendering surface, including
the code-snippet and source-span components. The injection-sink rule passes over
the rewritten tree.

### `adr-guardrails` (11)

ADR-001/002/003 still ported without weakened constraints; production sources
still free of banned patterns; MCP Sampling, raw-code persistence, doc-body
inlining, repo writes outside the PR proposal, and network calls inside
`packages/core` all still detected; merges and default-branch mutation still
rejected even inside the PR-proposal modules.

Relevant to this phase: the new graph engine added a Web Worker, a Pixi backend
and a bundle-measurement script, none of which introduced network access into
`packages/core` or any other banned pattern.

### `scope-fidelity` (13)

All eleven forbidden boundaries still rejected — `local-cli`, `team-ui`,
`external-billing`, `non-github-provider`, `marketplace`,
`skill-security-scanning`, `direct-autonomous-writes`, `raw-code-persistence`,
`always-loaded-generated-context`, `deprecated-mcp`,
`unsupported-savings-claims` — with a negative fixture present for each, and the
current MVP product surface still accepted.

`accepts the current MVP product surface` is the case that would fail if this
phase had smuggled a feature in behind a restyle. It passes, which is
independent corroboration of the plan's "no feature additions/removals"
constraint.

## 3. What F4 does not cover

These suites check boundaries and patterns, not visual correctness. A restyle
that made a screen unusable while touching no banned pattern would pass F4
cleanly. F1's browser suites and F3's contrast audit are what cover that, and
they carry their own stated limits (`/auth/*` and `/app/*` unreachable —
OQ-008; canvas keyboard access unmeasured — OQ-006).
