# F3 — perf smoke, bundle budget, axe contrast within budget

> Plan text: "perf smoke + bundle budget + axe contrast evidence present and
> within budgets."

**Verdict: PASS on all three budgets, with two stated limits on coverage.**

Full method, raw numbers and the fixes are in
[`../task-9.md`](../task-9.md); this file is the gate ruling.

Measurement host: AMD Ryzen 7 9800X3D (8C/16T), 61.6GB, Node v24.14.0,
Windows 11 10.0.26200, Chromium via `@playwright/test` 1.62.1.

## 1. Perf smoke — 500-node frame budget

Budget: **p95 simulated frame < 16.7ms**, method documented.

`tests/graph-perf.test.ts`. The measured quantity is the CPU work the renderer
owns on the main thread — `buildRenderFrame()`, the O(nodes) hot spot — plus the
worker's force tick, each timed with `performance.now()` over 240 (resp. 120)
frames after a 60-frame warm-up, on `createFixtureGraph(500)` laid out by
`runForceLayout` (500 nodes, 493 edges, seed 7). The camera pans and zooms
across all three LOD bands and the glow map is rebuilt every frame, so the
label grid, badge pass, edge pass and glow lookups are all exercised and nothing
is memoised away.

| measurement | p50 | **p95** | max | budget | margin |
| --- | --- | --- | --- | --- | --- |
| `buildRenderFrame(500)` | 0.215ms | **0.385ms** | 2.061ms | 16.7ms | **43×** |
| + Far-zoom community collapse | 0.158ms | **0.267ms** | 1.364ms | 16.7ms | 63× |
| worker tick + transferable encode | 0.689ms | **1.113ms** | 1.569ms | 33.3ms (30Hz) | 30× |

The worst single frame in the entire run — 2.061ms — is still 8× inside budget.

A fourth case guards the thing that will actually regress: frame cost from 125
to 500 nodes grew **×2.56** where a quadratic lookup would give ×16. That
assertion fails on an accidental `array.find()` in the node or edge pass long
before the 16.7ms budget would notice.

**Limit:** GPU raster time is not in this number and cannot be measured
headlessly. That the canvas renders at all, and that ten mount/unmount cycles
leak no WebGL context, is covered in the browser by
`tests/e2e/brain-map.spec.ts`. Behaviour above 3,000 nodes is also not measured;
the plan specifies 500 and the collapse path is measured at that size.

## 2. Bundle budget — graph route < 450KB gz

Budget: **< 450KB gz initial JS for the graph route, Pixi included, or a
documented exception.** No exception is needed.

Turbopack prints no per-route table and `.next/build-manifest.json` lists only
the shared root chunks, so `scripts/measure-route-bundle.ts` discovers the chunk
**set** empirically (serve the production build, record every JS URL the browser
requests, tagged by load phase) and computes **sizes** deterministically
(`zlib.gzipSync` at level 6 from the files on disk). The script exits non-zero
over budget.

| route | render-blocking (`document`) | **all JS by idle, Pixi included** | verdict |
| --- | --- | --- | --- |
| **`/` — dashboard / brain map** | 160.2KB gz (11 chunks) | **411.3KB gz (30 chunks)** | **OK, 38.7KB to spare** |
| `/graph?node=req-auth` | 146.5KB gz | 224.2KB gz | OK |
| `/findings` | 211.8KB gz | 211.8KB gz | OK |

`idle` is the honest tier for this budget: `dynamic(ssr:false)` means Pixi does
not block first paint, but it is requested unprompted on mount, so a user on the
dashboard does download it. Brotli, for reference, is 354.9KB on `/`.

Reconciling with the Wave 3 handoff's "574.1KB gz across every route combined":
that summed all 41 client chunks in the build; 30 of them are reachable from `/`.

**Headroom is real but thin.** The 19 lazy chunks past `load` total 251.1KB gz.
Any further heavy client dependency on the dashboard route breaks this budget
first. Recommend keeping `measure-route-bundle.ts` in CI.

Also recorded (outside the JS budget, and the input that closes OQ-002): `/`
fetches 12 woff2 subsets totalling **285.1KB**, versus 2.0MB for the single
whole-family file `next/font/local` would force — the dynamic-subset decision is
confirmed by measurement, not assumed.

## 3. axe-core contrast — AA, dashboard and findings, both themes

Budget: **no AA failures for standard text.**

`tests/e2e/a11y-contrast.spec.ts`, 4 cases, reports in
[`../task-9/`](../task-9).

### The first run failed, and the failures were real

| theme | screen | violations, first run |
| --- | --- | --- |
| dark | dashboard | 0 |
| light | dashboard | 0 |
| dark | findings | **11** |
| light | findings | **22** |

Two distinct causes: the derived `--faint` token was below 3:1 in both themes,
and ADR-009-3's own light status colours fall between 3.25:1 and 4.68:1 when
they carry 9–11px badge text on paper white.

### Fixed in the tokens file; nothing suppressed

`--faint` was raised (dark `#5A6478` → `#848EA2`, worst case 2.57 → 4.63:1;
light `#8A8F9E` → `#666C7B`, 2.82 → 4.58:1), preserving the `text > muted >
faint` order. The ADR palette was **not changed**; AA-safe text-only siblings
(`--brand-text`, `--verified-text`, `--inferred-text`, `--info-text`) were added
and applied to the six rules that paint small status text, while nodes, dots,
rings, tints and borders keep the ADR values. Raised as **OQ-009** for a
planning ruling because the marketing site inherits the same palette.

### Second run

| theme | screen | violations | incomplete | passing nodes |
| --- | --- | --- | --- | --- |
| dark | dashboard | **0** | 45 | 28 |
| light | dashboard | **0** | 45 | 28 |
| dark | findings | **0** | 0 | 71 |
| light | findings | **0** | 0 | 71 |

**Limit 1 — the 45 `incomplete` results are not passes.** axe could not compute
a background: 38 elements contain an inline SVG icon, 6 sit on the title band's
gradient, 1 is too short to classify. All are token-driven surfaces and the
browserless token-contrast suite covers the same pairings arithmetically, but
axe did not confirm them and this gate does not pretend it did.

**Limit 2 — scope is the two screens the plan names.** The WebGL canvas and its
transparent DOM hit layer are excluded by design (axe reads computed CSS and
cannot see either), and `/auth/*` (500) and `/app/*` (no Supabase) remain
unreachable in this environment — OQ-006 and OQ-008, both still open.

### Backstop added

`tests/design-tokens.test.ts` gained a `token contrast (WCAG 2.2 AA)` suite that
parses `tokens.css`, resolves `var()` aliases, computes WCAG 2.2 relative
luminance and asserts every text token clears 4.5:1 against `--bg`, `--surface`,
`--surface-2` and `--code-bg` in both themes. It fails the instant a token stops
being legible, without waiting for a screen to use that pairing, and it runs in
`pnpm test` rather than requiring a browser. Its own arithmetic is calibrated
against black-on-white = 21:1.
