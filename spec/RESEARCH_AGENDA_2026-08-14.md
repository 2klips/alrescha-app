# Arr Phase 2 연구·개발 아젠다 (2026-08-14, ADR-009)

> 1차 구현(MVP, 27/27) 완료 후의 연구·개발 지시 8건. 각 항목은 [담당]과 [산출물]을 명시한다. 담당: **연구**=리서치 에이전트/기획 세션, **설계**=기획 세션(spec 개정), **구현**=코딩 에이전트(arr-app).

## 1. Data Brain 효율 고도화

- **목표:** 사용자 토큰 낭비 최소화 + 정확도 상승 + 다목적 유연성(질의·팩·위키·향후 팀 지표까지 한 기반).
- **접근:** ⑴ 벤치마크 반복과 연동(§3) — 회수 실패 사례 기반 랭킹·팩 개선 ⑵ 계층 로딩(발췌→요청 시 전문) ⑶ 팩 캐싱·증분 갱신 ⑷ 쿼리 플래너(`search_index`/`query_brain`/`get_artifact` 조합을 서버가 추천) ⑸ 임베딩 하이브리드는 결정론 우선 원칙 하에 후순위 실험.
- **담당:** 연구(기법 조사) → 설계(WORK_SPEC 개정) → 구현. **산출물:** 기법 조사 노트, Data Brain v2 설계, 벤치 게이트 통과.

## 2. Graph View 디자인 연구 + 에이전트의 그래프 활용

- **디자인(Obsidian 참조):** force 시뮬레이션 파라미터(반발·링크 거리·중심 인력), 줌 레벨별 LOD(라벨·노드 크기), 클러스터링·필터 UX, 발광(액세스 이벤트) 연출과 성능(500+노드 60fps) 공존. → 디자인 스펙 문서 + 프로토타입.
- **에이전트 활용 여부:** 그래프를 "보는 것"을 넘어 에이전트가 **탐색·질의**하게 — `query_brain` 관계 질의 확장, 이웃 확장(traverse) tool, GraphRAG류 근거와 비교 검증(효과는 벤치 과제로 측정 — 시각 그래프 자체가 아니라 그래프 구조 API가 에이전트에 유효한지 검증).
- **담당:** 연구 → 설계 → 구현. **산출물:** Graph View 디자인 스펙, graph-tool MCP 확장안, 효과 측정 과제.

## 3. 실질 벤치마크 확대

- 현행: 12과제×3회×3군, 게이트 NOT MET(-7.04pp/-55.3%tok) — 원인 분석·1차 수정 완료(`benchmarks/databrain/ITERATION-2026-08-14.md`).
- **확대안:** ⑴ 매니페스트 v2(개정 프롬프트) + 재실행 ⑵ 실레포 과제 비중 확대(현 2개 → 6개+, 외부 OSS 레포 포함) ⑶ 모델 2종 이상(gpt-5-nano + claude 계열) ⑷ 반복 수 상향(3→5)과 신뢰구간 표기 ⑸ 지표 하네스 주입 실험(§5-4)을 같은 하네스에 통합.
- **담당:** 설계(과제 설계) → 구현(하네스 확장) → 실행(예산 승인 필요). **산출물:** 벤치 v2 리포트 — 게이트 통과 시에만 효율 주장 게시.

## 4. 등록 플로우: 레포 URL + Vercel식 자동 분석 + 로컬 업로드

- **레포 URL 등록:** 현행 GitHub App 설치 플로우에 "레포 주소 붙여넣기 → 해당 레포만 설치 유도" 경로 추가 (Vercel의 Import Git Repository UX 벤치마크).
- **푸시 → 자동 분석:** webhook 파이프라인은 구현 완료 — Vercel 배포 카드처럼 "커밋별 분석 카드(상태·영수증·발견 델타)" UI로 노출 강화.
- **로컬 프로젝트:** ⑴ 1순위 — 로컬 CLI 인제스트(`arr push` 스타일: 스캔 메타데이터만 업로드, 원본 비저장 원칙 유지 — Phase 2로 미뤄둔 로컬 CLI의 부활 형태) ⑵ 보조 — zip 업로드(비Git 사용자용, 동일 비저장 원칙). Git 우선 원칙은 유지하되 진입 장벽 제거용.
- **담당:** 설계 → 구현. **산출물:** 온보딩 v2 스펙 + 구현.

## 5. 팀 솔루션 (바이브 코딩 팀) — 핵심 연구 항목

> 방향: "옛 개발 문화의 PR·리뷰어 기반 역량 검증을 바이브 코딩계로 이식한다."

- **5-1 프롬프트 기록·평가:** 팀원의 프롬프트 작성 내역을 기록(가능 소스: MCP log_progress 확장, 에이전트 세션 export, IDE 훅 — **프라이버시 원칙 재설계 필요**: 현행 "프롬프트 원문 비저장" 가드레일과 충돌 → 팀 옵트인·범위 명시로 개정 검토), 프롬프트에 평점·리뷰(리뷰어 문화).
- **5-2 AI 프롬프트 코칭:** 프롬프트를 AI가 점검 — 누락 요소(수용 기준·제약·컨텍스트 참조) 지적, 개선안 제안 (프롬프트 엔지니어링 보조). 크레딧 과금 판단 잡으로.
- **5-3 기여도:** 커밋·영수증·발견 해소·프롬프트 기록을 연결해 "누가 어떤 요구사항을 증명까지 끌고 갔나"로 기여도 산출 — LOC가 아니라 **증거 기반 기여도**.
- **5-4 지표:** DORA 4지표의 바이브 코딩 대응물 + **독자 지표(가칭 VIBE Index)** 연구 — 후보 축: 프롬프트→증명 리드타임, 재생성률(re-prompt rate), 드리프트 발생/해소율, 검증 커버리지 증가율, 토큰 효율. **추가 검증 실험:** "이 지표를 높여라"를 하네스로 주입했을 때 에이전트 정확도가 실제로 오르는지 벤치 하네스로 A/B 측정 (지표의 goodharting 여부 검증 포함).
- **담당:** **연구(외부 조사 — 진행 중, 리서치 에이전트)** → 설계(팀 스펙 + 프라이버시 ADR) → 구현. **산출물:** 지표 연구 보고, 팀 기능 스펙 v1.

## 6. 프로젝트 점검 대시보드

- 통합 뷰: 진척도·todo·남은 작업(기존 progress) + 발견 문제(findings) + **문서 점검·요약**(신선도·요약은 `inferred` 라벨 판단 잡) + **취약점**: ⑴ 문서·드리프트 기반 위험 ⑵ 의존성 감사 수집(npm audit/CI 아티팩트 인제스트 — 자체 스캐너는 계속 비목표, ADR-009-4).
- **담당:** 설계 → 구현. **산출물:** 점검 대시보드 스펙(§8 UI 재구성과 통합).

## 7. 디자인 시스템 "Ink & Seal" (ADR-009-3 채택)

- 한국어 우선, 관용 영단어(Dashboard·Graph·Findings·Receipt 등)는 영어 유지. 다크 기본 + 라이트("종이" 모드 — 기존 페이퍼 아이덴티티 재활용).
- 폰트: **Pretendard Variable**(본문·헤드라인) + **IBM Plex Mono**(수치·코드·로그).
- 토큰: Dark bg `#0B0E14` / surface `#141926` / line `#232B3D` / text `#E8ECF4` / muted `#8A94A8` · Light bg `#FAF7F1` / surface `#FFFFFF` / line `#E3DDD0` / text `#20242E` · 브랜드 주홍(도장) `#FF5A45`(D)/`#D6402E`(L) · verified `#3DDC97`/`#1E8A5E` · inferred `#F5B84A`/`#B07A14` · info/graph `#6C9EFF`/`#3B6FDB`.
- 노드 색 규약 유지: 문서 blue · 요구사항 주홍 · 코드 green · 테스트 amber.

- **대시보드(그래프 뷰)가 메인** — 전면 그래프 + HUD 구조(ADR-004)를 §7 디자인 시스템으로 재구현. 마케팅 사이트도 동일 시스템으로 교체.
- 실행: 코딩 에이전트 세션(웨이브 방식) — 선행 조건: §2 그래프 디자인 스펙, §7 토큰 확정(완료).
