## ADR-014 — OQ-015 판정: tree-sitter 미채택, 엔진 체인 유지 + 심볼 provenance 기록 (2026-08-17)

**날짜:** 2026-08-17
**상태:** 채택
**근거:** `OPEN_QUESTIONS.md` OQ-015. Phase 2B todo 7 ⑵가 요구한 "tree-sitter 다언어 AST 1순위 승격"을 조사한 결과, 도입 방식 어느 쪽도 지금의 비용·제약을 정당화하지 못한다.
**해결 대상:** BUILD_PLAN_PHASE2B todo 7 ⑵의 문구. ADR이 계획보다 상위이므로 이 결정이 그 요구를 개정한다.

### 결정

1. **tree-sitter를 지금 채택하지 않는다.** 대신 현행 **엔진 체인**을 정식 설계로 승격한다 — ts/js는 TypeScript 컴파일러 **AST**(진짜 파싱), Python·Go는 결정론 구조 파서.
2. **선택적(optional) 의존성은 금지한다.** tree-sitter가 "있으면 쓰고 없으면 폴백"이면 같은 커밋이 환경에 따라 다른 심볼을 낳는다 — 이는 CLI/GitHub 두 경로가 동일 그래프를 만든다는 ADR-013의 보장을 정면으로 깬다. 따라서 선택지는 **전면 채택 아니면 미채택** 둘뿐이며, 이번 판정은 후자다.
3. **전면 채택의 비용이 현재 편익을 넘는다.** 네이티브 바인딩은 node-gyp 빌드를 요구해 Windows 개발 환경과 `arr push` CLI 배포에 부담이고, wasm 경로는 런타임+그래머 바이너리 수 MB를 CLI 패키지에 싣는다. 반면 제품이 필요로 하는 것은 **심볼 메타데이터**(이름·종류·라인 스팬)이지 의미 분석이 아니며, 주 언어(ts/js)는 이미 정확한 AST로 읽고 있다.
4. **대신 정직성을 강화한다 — 심볼 provenance 기록.** 각 아티팩트가 `metadata.symbolEngine`으로 **어느 엔진이 그 심볼을 읽었는지**를 남긴다(`typescript-ast` / `python-structural` / `go-structural`, 코드 아닌 아티팩트는 null). 정밀도를 균일하다고 가정하지 않게 만드는 것이 목적이며, 이는 verified/inferred 구분과 같은 원칙의 적용이다. `metadata`는 **병합**하며 덮어쓰지 않는다 — 판단 잡이 쓴 요약이 재스캔에서 살아남아야 한다.
5. **재검토 트리거를 명시한다.** ⑴ ts/js/py/go 밖 언어가 주 언어인 레포 수요가 실제로 관측되거나 ⑵ 벤치마크에서 심볼 품질에 기인한 실패가 측정되면, 그때 전면 채택(⑴ wasm 우선)을 다시 판정한다. 언어 추가는 구조 파서 확장으로 대응하되 언어별 픽스처 테스트를 함께 요구한다.

### 의미

"측정 없는 수치를 말하지 않는다"를 의존성 결정에도 적용했다. 수요가 측정되지 않은 능력을 위해 공급망·크기·빌드 복잡도를 먼저 지불하지 않되, 대신 **현재 정밀도가 어디서 왔는지를 제품이 스스로 밝히게** 만들었다. 결정은 되돌릴 수 있고, 되돌릴 조건도 위에 적혀 있다.

## ADR-013 — OQ-013 판정: 스코프 경계 재정의 — 로컬 인제스트 허용(메타데이터만) + 팀 표면 조건부 허용 (2026-08-17)

**날짜:** 2026-08-17
**상태:** 채택
**근거:** `OPEN_QUESTIONS.md` OQ-013 (Phase 2B todo 3 `arr push` CLI가 local-cli 스코프 가드레일과 충돌), 제품 방향 확정 — 주 경로는 GitHub 실시간 연동(ADR-003), 로컬 경로는 GitHub 경로와 동일하게 **메타데이터만** 인제스트하고 깃허브 푸시를 유도한다(ADR-006-2와 정합).
**해결 대상:** ADR-002 §5의 "로컬 CLI 드리프트 체커 2단계 연기"와 WORK_SPEC §12 비목표의 local-cli 항목. Phase 2B가 그 "2단계"임을 확인하고 경계를 다시 긋는다.

### 결정

1. **로컬 인제스트 경로를 허용한다.** 대상은 특정 도구가 아니라 **경로 전체**다 — todo 3의 CLI(`arr push`)뿐 아니라 이후 웹 업로드 UI 등 어떤 형태의 로컬 인제스트든 이 ADR 하나로 커버한다. 단 불변 조건: **스캔·파싱은 로컬에서 수행하고 서버에는 메타데이터만 전송·저장한다.** 원본 코드 비저장 하드 룰(WORK_SPEC 가드레일)은 이 경로에서도 동일하게 성립하며, 업로드 페이로드에 파일 본문이 없음을 테스트로 증명해야 한다.
2. **local-cli 스코프 경계를 교체한다 — 삭제가 아니라 대체.** `scripts/verify-scope-boundaries.ts`의 `scanLocalCli`("CLI 존재 금지")를 **"원본 코드 전송·저장 금지"** 경계 스캐너로 교체한다. 지키려던 실체(코드 비저장)는 raw-code-persistence 가드레일과 새 스캐너가 더 정확하게 커버한다. 교체 시 위반(파일 본문을 업로드 페이로드에 넣는 코드)을 일부러 심어 새 스캐너가 잡아내는지 재증명한다(`tests/scope-fidelity.test.ts` 갱신). 가드레일 약화 금지 원칙 준수.
3. **team-ui 경계도 같은 원리로 교체한다.** `scanTeamUi`("팀 UI 금지")는 Wave 4 todo 9(팀 워크스페이스)에서 동일 충돌이 확정 재발한다. 팀은 ADR-006(1순위 후속 격상)·ADR-011(프라이버시 모델)로 이미 의결된 방향이므로, 경계를 **"ADR-011 음성 테스트(동의 없는 수집·원문 혼입·동의 상태 노출 금지) 없이는 팀 표면 추가 금지"**로 교체한다. 두 경계를 한 작업 단위에서 처리해 절차 중복을 없앤다.
4. **WORK_SPEC §12 비목표 목록을 이에 맞춰 개정한다.** local-cli·team-ui 항목을 새 경계 문구로 대체하고, "원본 코드 전송·저장"과 "ADR-011 미준수 팀 표면"을 명시적 비목표로 남긴다.
5. **온보딩과 로컬 인제스트 도구는 깃허브 푸시를 유도한다.** 로컬 경로는 대체재가 아니라 가교다 — CLI 출력·온보딩 카피에 GitHub 연결 안내를 포함한다(ADR-006-2 재확인).
6. **원본 코드 보관(유료 옵션)은 결정하지 않는다.** "메타데이터만으로 부족하다"는 실제 사용자 수요 신호가 나오기 전까지 비목표를 유지한다. 필요 시 별도 ADR로 다루며, OPEN_QUESTIONS에 후보로만 기록한다.

### 의미

가드레일이 지키던 것은 "CLI가 없는 상태"가 아니라 "사용자 코드가 서버에 남지 않는 상태"다. 대리 지표가 본래 목적과 충돌하기 시작했으므로 본래 목적 쪽으로 경계를 다시 그었다. 경계는 풀리는 게 아니라 정확해진다.

## ADR-012 — OQ-011 판정: 정확도 주장 철회, 토큰 주장 유지 (2026-08-17)

**날짜:** 2026-08-17
**상태:** 채택
**근거:** 벤치 v3 하네스가 도입한 **구간 기반 게이트**를 v2 데이터(36 페어)에 적용한 결과 — 정확도 Δ +3.66pp, **95% CI [−6.19, +14.27]pp → 비열등 불성립**. 토큰 −55.97%, CI [36.71, 67.70]% → 통과.

### 결정

1. **정확도 주장은 공개 표면에서 내린다.** 사이트 히어로의 "+3.66pp"를 헤드라인에서 제거한다. 삭제가 아니라 **강등**이다 — 측정값은 리포트에 그대로 남고, 사이트에는 "정확도는 v3에서 재검증 중"으로 표기한다. 점추정만 보고 이득을 단언하는 것은 RULE 4("측정 없는 숫자를 말하지 않는다")의 위반이며, 표본이 작을 때 점추정을 헤드라인화하는 것도 같은 종류의 거짓 정밀도다.
2. **토큰 주장은 유지하되 구간을 병기한다.** "−55.97%"는 CI 하한 36.7%가 목표(30%)를 넘으므로 유효하다. 다만 앞으로 모든 효율 수치는 **점추정 단독 표기 금지, 구간 병기 필수**.
3. **v2 리포트는 그대로 공개 유지.** 사후 수정하지 않는다 — 발표 당시의 측정을 있는 그대로 남기는 것이 정직성의 실체다. v3 리포트가 나오면 두 리포트가 나란히 존재한다.
4. **v3 게이트는 구간 기준을 유지한다.** 더 어려워지는 방향의 기준 강화는 되돌리지 않는다. v3의 페어 수는 36→200으로 늘어 검정력이 확보된다.
5. **`claude-sonnet-5` 모델 ID 확인 완료** — 유효한 식별자다. v3 다중 모델 실행에 사용한다.
6. **`run.corpusCommit` 기록 채택** — 실레포 과제 컨텍스트가 작업 트리에서 오므로 커밋 SHA를 리포트에 남긴다(비용 0, 재현성 필수).

### 의미

이 결정은 우리가 만든 제품의 원칙을 우리 자신에게 적용한 첫 사례다. 더 엄격한 측정법을 도입했더니 우리 주장이 먼저 걸렸고, 그래서 주장을 내렸다. 제품이 사용자에게 요구하는 것("증거 없으면 inferred")과 같은 기준이다.

## ADR-011 — 팀 기능 프라이버시 모델 (2026-08-16)

**날짜:** 2026-08-16
**상태:** 채택
**근거:** `RESEARCH_TEAM_METRICS_2026-08-14.md` (Claude Code OTel 옵트인 규범, SpecStory 로컬 우선, METR 자가보고 오차), `REVIEW_EXTERNAL_PROJECTS_2026-08-16.md` H4 (recent-prompts 로컬 파일 선례)
**해결 대상:** 팀 프롬프트 기록(§5-1)은 기존 가드레일 "access_events에 프롬프트 원문 비저장"(ADR-004)과 충돌한다. 이 ADR이 그 경계를 다시 긋는다.

### 결정

1. **이중 옵트인.** 프롬프트 기록은 ⑴ 워크스페이스 관리자가 기능을 켜고 ⑵ **각 팀원이 개별 동의**해야만 수집된다. 동의하지 않은 팀원의 프롬프트는 어떤 형태로도 수집되지 않으며, 동의 여부 자체가 팀에 노출되지 않는다.
2. **로컬 우선(local-first).** 기본 저장 위치는 **사용자 레포 내 로컬 파일**(gitignore 기본)이다. 서버 동기화는 팀원이 명시적으로 켤 때만 일어난다. 로컬만 쓰는 사용자도 개인 프롬프트 코칭(§5-2)을 온전히 쓸 수 있어야 한다.
3. **메타데이터 우선 / 원문은 예외.** 서버 기본 저장 대상은 **메타데이터·파생 점수**(시각, 툴명, 대상 노드, 토큰 수, 루브릭 점수)뿐이다. **프롬프트 원문은 팀원이 "원문 동기화"를 따로 켠 경우에만** 저장하며, 켜져 있어도 원문 열람 권한은 기본적으로 **작성자 본인**에게만 있다. 팀 공유는 작성자가 개별 프롬프트를 명시적으로 공개(share)할 때만.
4. **관측과 인사평가의 분리.** VIBE Index·기여도는 개선 도구이지 감시 도구가 아니다. **개인 점수는 본인에게, 팀 뷰에는 집계·분포만** 표시한다. 개인 간 비교 표는 워크스페이스가 정책으로 명시 활성화해야 하며, 활성화 사실이 전 팀원에게 고지된다. 제품 카피 어디에도 "직원 평가/감시" 프레이밍을 쓰지 않는다.
5. **자가보고 금지.** 모든 지표는 로그·커밋·영수증에서 자동 산출한다 (METR: 체감 +20% vs 실제 −19%).
6. **삭제권.** 팀원은 언제든 자신의 기록 전체를 삭제할 수 있고, 삭제는 파생 점수·집계에서도 즉시 반영된다. 워크스페이스 삭제 시 전량 파기. 보존기간은 Free 30일 / Pro 무제한(사용자 설정 가능).
7. **Goodhart 게이트.** 어떤 VIBE 지표도 **하네스 주입 A/B에서 "지표↑ AND 정확도↑"를 통과하기 전에는 제품에 노출하지 않는다**. 지표만 오르고 정확도가 그대로거나 떨어지면 그 지표는 폐기·재설계한다.

### 기존 가드레일과의 관계

ADR-004의 "access_events에 프롬프트 원문 비저장"은 **불변**이다 — 발광용 이벤트 스트림에는 앞으로도 원문이 들어가지 않는다. 프롬프트 기록은 그와 **분리된 별도 저장소·별도 동의·별도 보존 정책**을 갖는다. 두 경로가 섞이지 않음을 테스트로 강제한다.

## ADR-010 — Phase 2A 완료 + 팔레트 접근성 판정 + 네이밍 정리 (2026-08-16)

**날짜:** 2026-08-16
**상태:** 채택
**근거:** `arr-app` main 병합(ed06d93) — 10 todos·4 waves, 테스트 244→**416**, Playwright **49/49**, F1~F4 통과. 핸드오프 문서 `arr-app/docs/design-tokens.md`.

### 결정

1. **Phase 2A 완료 승인.** 대시보드가 Obsidian급 전면 그래프(graphology + d3-force Worker + Pixi v8)로 전환됐고, 다크 기본 + 라이트("종이") 테마·한국어 우선 카피가 전 화면에 적용됐다. 측정값: 500노드 프레임 p95 **0.385ms**(예산 16.7ms, 43배 여유), 그래프 라우트 초기 **160.2KB gz** / 유휴 포함 **411.3KB gz**(예산 450KB), axe AA 위반 33건 → **0건**.
2. **OQ-009 판정 — ADR-009-3 팔레트 유지 + 텍스트 전용 파생 토큰 채택.** 라이트 테마의 상태색(verified/inferred/brand/info)은 3.25–4.68:1로 소형 텍스트 AA(4.5:1) 미달이 실측됐다. **브랜드 정체성 색은 그래프 노드·점·링·틴트에 그대로 유지**하고, 텍스트에는 어둡게 파생한 `--*-text` 형제 토큰을 쓴다. ADR-009-3의 팔레트 값 자체는 개정하지 않는다. **마케팅 사이트 교체 시 동일 규칙 적용**(design-tokens.md §3.2).
3. **OQ-010 — 잔여 `specproof` 네이밍 정리를 별도 작업으로 승인.** 패키지명(`@specproof/web`)·데모 레포 문자열(`specproof/drifted-demo`)·README 푸터에 구 제품명이 남아 있다. **사용자 가시 문자열 우선**으로 정리하고, 패키지명 변경은 plan-compliance 경로 상수를 함께 손봐야 하므로 같은 작업 단위에서 진행한다. Phase 2B 착수 전 처리.
4. **미검증 항목 명시(정직성):** OQ-006(캔버스 히트 레이어는 axe 대상에서 제외됨, 600 타깃 키보드 순회 비용 미측정), OQ-008(`/auth/*` 500·`/app/*` Supabase 필요로 양 테마 명암비 **미검증** — "통과"가 아님), OQ-007(HUD 여백 26px는 여전히 튜닝 상수, 구조적 해결 필요). 이들은 Phase 2B 범위로 이월한다.

## ADR-006 — 기획 재점검: 타깃·진척 기록·하네스 뷰·개인 라이브러리 (2026-08-09)

**날짜:** 2026-08-09
**상태:** 채택

### 결정

1. **타깃 재정의:** "바이브 코딩 **개인 + 팀** 솔루션"으로 포지셔닝. 구현 순서는 MVP = 솔로, **팀(워크스페이스 초대·공유 그래프)은 1순위 후속**(2단계 최우선 항목으로 격상).
2. **새 프로젝트 온보딩:** 새 프로젝트도 **깃허브에 먼저 푸시**하도록 온보딩에서 안내(빈 레포 생성 가이드 포함). 퍼블릭 레포여도 SpecProof 워크스페이스는 GitHub과 동일하게 **본인만 접근**(RLS — 기존 설계 확인).
3. **작업 기록 양식 + 진행 대시보드 (MVP, 경량):** 에이전트에게 **구조화 기록 양식**(task·status·summary·refs, 호출당 목표 ≤150 토큰)을 스킬/최소 인덱스로 제공하고, `log_progress` 확장 + TODO.md 파싱으로 **진척율·todo·최근 작업 대시보드**를 구축한다. **토큰 낭비 금지 원칙**: 기록은 짧은 구조화 1콜, 서술형 보고 양식 금지, 기록 강요 리마인더 금지.
4. **하네스 인벤토리 대시보드 (MVP):** 프로젝트에서 발견된 skill·plugin·rules·MCP 설정을 "무엇이 있고 어느 에이전트에 활성인가" 인벤토리로 표시 — 지시문 린트(토큰 비용·모순)와 한 화면으로 통합.
5. **개인 공용 라이브러리 (MVP는 저장·조회만):** 프로젝트에서 발견된 skill·하네스 요소를 "내 라이브러리"에 저장·조회. **새 프로젝트로 가져오기(PR 생성)와 Data Brain 템플릿 이식은 2단계.** 공개 마켓플레이스는 계속 비목표.
6. **Data Query 보강:** `search_index` 외에 구조화 질의(`query_brain`: 유형·상태·관계 필터)를 MCP에 추가 — Data Brain "사용 가능한 용법 전부" 원칙의 일부.

## ADR-005 — Data Brain 명명 + 효율 벤치마크 필수화 (2026-08-09)

**날짜:** 2026-08-09
**상태:** 채택

### 결정

1. **Data Brain:** SpecProof가 레포마다 구축하는 지식 시스템의 공식 명칭. 구성 = ① 증거 그래프 DB(구조화 저장) ② LLM Wiki 레이어(문서 간 상호링크·백링크 + `inferred` 표시된 AI 요약, 주문형 서빙 전용) ③ Data Index(결정론 검색 색인) ④ 주문형 서빙(MCP·컨텍스트 팩). 목표는 단일: **같은 작업을 더 정확하게, 더 적은 토큰으로.** 모든 용법(위키·DB·색인)을 조합하되 "항상-로드 금지"(ADR-002/ETH) 원칙은 불변.
2. **효율 벤치마크 필수화:** "정확도가 올라가고 토큰이 줄어든다"는 SpecProof의 핵심 주장을 **실측 A/B 테스트로 증명하는 벤치마크 하네스**를 MVP 필수 산출물로 포함한다. 같은 과제를 (A) 베이스라인 에이전트 vs (B) SpecProof Data Brain 연결 에이전트로 수행, 성공률·토큰·툴콜 수를 측정. 시장 조사 R1 리스크(ETH 연구)에 대한 직접 응답이며, "측정 없는 숫자 주장 금지" 원칙의 실행 수단. 목표치(가설): 정확도 비열등 이상(+5%p 목표), 토큰 30%+ 절감 — 미달 시 파이프라인 개선 후 재실행, 결과는 수치 그대로 공개.

## ADR-004 — 핵심 경험 재조정: 세컨드 브레인 그래프 + 데이터 색인 + 라이브 에이전트 활동 (2026-08-09)

**날짜:** 2026-08-09
**상태:** 채택 (ADR-002 "보증 리드"의 표면 우선순위를 개정, 보증 자체는 유지)

### 결정

1. **메인 대시보드 = 세컨드 브레인 그래프 (전면 + HUD).** Obsidian graph view처럼 그래프가 화면 전체를 채우고, 지표·발견·라이브 활동 피드는 반투명 오버레이(HUD)로 얹는다.
2. **데이터 색인(Data Index)이 1급 기능.** 솔루션이 레포의 문서·요구사항·코드 메타데이터를 구조화 색인으로 구성하고, 에이전트는 MCP(`search_index`, `get_artifact`, `request_context_pack`)로 쉽게 찾아 참조한다. MVP 검색은 결정론(키워드·경로·태그·그래프 이웃), 임베딩 검색은 2단계.
3. **라이브 에이전트 활동(뉴런 발광).** 에이전트가 MCP로 데이터를 조회할 때마다 access event를 기록하고, 대시보드 그래프에서 해당 노드·엣지가 뉴런처럼 발광(pulse)한다. 실시간 채널(SSE/Supabase Realtime), 본인 워크스페이스만.
4. **보증(드리프트·영수증)은 유지하되 2순위.** 발견은 그래프 노드 배지·HUD 패널로 통합 표시. 유료 차별화 레이어로 존속 — ADR-001의 원래 구도(허브 진입 + 보증 차별화)로 부분 회귀.

### 근거·유의

- "내 에이전트가 내 세컨드 브레인을 쓰는 게 보인다"는 강력한 데모/차별화 포인트 (경쟁 조사에서 유사 기능 없음).
- ETH 제약과 정합: 색인은 항상-로드가 아니라 **MCP 주문형 서빙의 기반**이다. 정적 파일 최소 인덱스 원칙(ADR-002) 불변.
- 제품명 SpecProof·증거 정체성 유지 — 그래프는 "증거가 사는 곳", 발광은 "증거가 사용되는 순간"으로 내러티브 통합.

## ADR-003 — 전달 형태: GitHub-우선 웹 SaaS (2026-08-09)

**날짜:** 2026-08-09
**상태:** 채택 (ADR-002의 "전달 형태" 부분을 개정)

### 결정

사용자 플로우는 **"GitHub에 푸시하면 자동 분석"**이다. 로컬 코드 업로드/설치형 CLI가 아니라:

1. **수집:** GitHub App — 웹에서 레포 연결 1회 → 푸시마다 webhook으로 서버가 문서+코드 메타데이터 스캔. 읽기 전용 최소 권한.
2. **분석 실행 위치:** DocsHub 서버. 드리프트 엔진은 결정론 우선이라 서버 COGS가 낮고, AI 판단 단계만 크레딧 과금(하이브리드 결정 유지) + BYOK 옵션.
3. **결과 표면:** 웹 대시보드 (드리프트 발견·문서 인벤토리·증거 그래프·영수증). 기존 대시보드 목업 비전 계승.
4. **MCP:** 유지하되 DocsHub가 호스팅 (로컬 설치 불필요, 사용자별 토큰). 에이전트는 호스티드 MCP로 주문형 컨텍스트 팩·발견 사항을 받는다.
5. **로컬 CLI 드리프트 체커:** 2단계로 연기.
6. **테스트 증거:** 서버는 테스트를 직접 실행하지 않는다. 사용자 CI(GitHub Actions)의 테스트 리포트(JUnit/JSON 아티팩트·체크런)를 수집해 `verified` 판정, 없으면 `inferred`로 강등.
7. **레포 쓰기:** MVP는 advisory-only — 최소 인덱스 섹션도 PR 제안으로만. 직접 쓰기/자율 유지보수는 2단계.

### ADR-002와의 관계

- 유지: 보증 리드 MVP, 주문형 로드 코어(ETH 대응 — 이제 호스티드 MCP가 서빙), $20 앵커 가격, 표준 채택(MCP 2026-07-28 stateless, SKILL.md, in-toto형 영수증), 검증/추론 분리, 솔로 우선(솔로 워크스페이스만 MVP, 스키마는 팀 확장 대비).
- 개정: "로컬 CLI/MCP 코어 + 로컬 무료"의 전달 형태 부분. 무료 코어 약속은 "무료 티어(레포 1개) + 호스티드 MCP + BYOK"로 이어받는다.
- 근거: 바이브 코더 온보딩 장벽 최소화(설치·워크플로 YAML 불필요), 대시보드 비전과의 정합, 결정론 엔진 덕에 서버 비용 통제 가능.

## ADR-002 — 코어 설계·MVP 순서·가격 (2026-08-09 시장 재검증 반영)

**날짜:** 2026-08-09
**상태:** 채택
**근거 자료:** `RESEARCH_UPDATE_2026-08-09.md` (에이전트 7건 병렬 조사, 1차 출처 검증)

### 결정 1 — 컨텍스트 코어는 주문형 로드(load-on-demand)

정적 컨텍스트 파일은 **최소 인덱스만** 유지하고, 작업에 필요한 문서는 MCP로 그때그때 서빙한다(progressive disclosure).

- 근거: ETH 취리히 연구(arXiv 2602.11988) — 정적 컨텍스트 파일은 성공률 개선 없이 비용 +20%; SkillsBench(arXiv 2602.12670) — 큐레이션된 주문형 지식은 +16.6pp.
- 금지: 자동 생성 문서를 항상-로드 컨텍스트에 넣는 설계. LLM 생성 요약은 `inferred` 표시 후 주문형으로만.
- 정적 파일에 남기는 것: 비추론가능(non-inferable) 정보만 — 커스텀 빌드 명령, 도메인 제약, DocsHub MCP 진입점.

### 결정 2 — MVP는 보증(Spec-to-Proof) 리드

ADR-001의 "허브 진입 + 보증 차별화"를 뒤집어 **보증으로 진입**한다. 첫 데모 가치: "머지된 코드가 스펙/문서와 어긋나면 플래그."

- 근거: 21개 제품 조사에서 requirement→구현→테스트 커밋 단위 추적은 완전 공백. Tessl $125M(지불의사 증거), Prelint PH 1위(솔로/소팀 수요 증거). 컨텍스트 허브 축은 Claude Code 네이티브·Antigravity·DeepWiki와 정면 충돌 + ETH 리스크 직격.
- 허브(문서 인벤토리·그래프·컨텍스트 팩)는 보증을 위한 **기반 데이터 레이어**로 뒤에 깔린다 — 별도 제품으로 팔지 않는다.
- 스킬 분석(충돌·토큰 오버헤드·인벤토리)은 보증 다음의 2번째 확장 축. 배포·보안 스캔은 만들지 않는다(플랫폼이 점유: Anthropic 자체 스캔 2026-08-06, Snyk×Vercel).

### 결정 3 — 가격은 $20 앵커 (SpecStory 패턴)

- Free: 레포 1개, 크레딧 50/mo, 히스토리 30일. 로컬 CLI/MCP 코어는 영원히 무료 + BYOK.
- Pro $20/mo: 무제한 레포, 달러 페그 크레딧(공개 단가표·라이브 미터·기본 상한), 무제한 히스토리, 토큰 절감 분석.
- Team $35/user/mo(또는 ~$300 플랫): 풀 크레딧, 공유 그래프, 드리프트 대시보드, 스킬 라이브러리. SSO는 모듈 애드온.
- 원칙: 실패한 실행에 과금 금지, 요금제 의미 중도 변경 금지(기존 구독자 grandfathering), 추상 이중 단위 금지.

### 표준 채택 (빌드 규범)

- MCP **2026-07-28 stateless 스펙**으로 신규 구축. Sampling/Roots/Logging 사용 금지(12개월 폐기 시계). SEP-2640(Skills over MCP) 추적.
- 배포 컨테이너: **Agent Plugins 1.0**(2026-08-06, OpenAI·Google·MS·Amazon·Cursor·Vercel) + SKILL.md/`.agents/skills/`.
- AGENTS.md 정본 산출 + Claude Code용 `@AGENTS.md` 래퍼 자동 생성.
- 증거 영수증: in-toto attestation(runtime-trace/scai) + Sigstore 서명 + OTel GenAI 트레이스 + **Agent Trace 브리지**(아무도 안 만든 연결 — 방어 기능). 자체 포맷 발명 금지.
- OKF는 임포트/익스포트만, 내부 모델 비결합. llms.txt는 저가 익스포트로만.

### ADR-001과의 관계

ADR-001의 통합 정의(증거 그래프)·경쟁 경계·설계 원칙은 유지. 진입 순서만 "허브 먼저"에서 "보증 먼저"로 변경. 2026-08-09 앞선 결정 4건(로컬코어+웹, 하이브리드 AI, 솔로 우선)도 유지 — 보증 리드는 CI 게이트가 아닌 **솔로 개발자의 로컬 드리프트 체크**부터 시작해 솔로 우선과 정합시킨다.

## ADR-001 — 통합 제품 포지셔닝

**날짜:** 2026-07-28  
**상태:** 채택

### 결정

다음 기능을 유지한다.

- second brain
- knowledge/evidence graph
- Skill 저장·불러오기
- Skill 분석
- harness 분석

제품 중심 포지셔닝:

> 기획이 실제 코드와 테스트로 증명됐는지 자동 추적하는 AI 개발 보증 시스템.

통합 정의:

> AI 개발 프로젝트의 기억·Skills·하네스·요구사항·코드·테스트 실행을 하나의 증거 그래프로 연결해, 에이전트가 무엇을 알고 어떤 규칙으로 작업했으며 결과가 실제로 증명됐는지 추적한다.

### 기능 역할

- second brain: 프로젝트 장기 기억
- graph: 기억·실행 자산·구현·증거의 공통 모델
- Skill registry: 반복 작업 자산의 저장·버전·배포
- Skill analyzer: 형식·공급망·권한·계약·실행 위험 분석
- harness analyzer: 실제 적용 instruction·Skill·MCP·hook·permission 계산
- assurance engine: requirement→code→test→receipt 판정

### 경쟁 경계

- Argo의 AI 회사·크루 실행 모델을 복제하지 않는다.
- GitHub Spec Kit·Kiro와 spec 생성 기능으로 경쟁하지 않는다.
- 어떤 agent/spec 도구가 생성했든 현재 commit의 증거를 독립 검증한다.

### 설계 원칙

- Agent Skills, MCP, OKF v0.2 등 기존 표준을 consumer로 지원
- AI 추론은 `inferred`, 실행 증거만 `verified`
- 모든 receipt는 commit·artifact·Skill·harness digest와 연결
- local-first, Git-native
- public Skill marketplace는 신뢰·분석·sandbox 이후
